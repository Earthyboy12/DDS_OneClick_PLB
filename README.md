# DDS-PLB One-Click | ระบบวิเคราะห์ข้อมูลเฝ้าระวังโรคดิจิทัล (DDS) จังหวัดพิษณุโลก

**DDS-PLB One-Click** เป็นเว็บแอปพลิเคชันสำหรับนำเข้า ตรวจสอบคุณภาพ และวิเคราะห์ข้อมูลการเฝ้าระวังโรคทางดิจิทัล (Digital Disease Surveillance: DDS) ในรูปแบบ Excel เพื่อสร้างตารางสรุปมาตรฐานและแผนภูมิความละเอียดสูงระดับ 4K สำหรับบรรยายในสไลด์และเอกสารทางวิชาการ

> **คำเตือน (Disclaimer)**: ในระหว่างการพัฒนาและสาธิต ระบบใช้ **ข้อมูลสังเคราะห์ (Synthetic Data)** ที่จำลองโครงสร้างและปัญหาคุณภาพข้อมูลจริงอย่างครบถ้วน มิใช่ข้อมูลผู้ป่วยจริงและห้ามนำไปอ้างอิงเป็นสถานการณ์ทางระบาดวิทยาจริง

---

## 🌟 จุดเด่นและสถาปัตยกรรมระบบ (Architecture)

- **Frontend**: React 18 + TypeScript + Vite + Tailwind CSS ออกแบบด้วยสไตล์ **Navy Sidebar, White Cards, Teal Accents** รองรับ 2 ภาษา (ไทยเริ่มต้น พร้อมสลับ English)
- **Backend**: Python 3.12 + FastAPI + pandas + openpyxl + statsmodels + scipy + matplotlib
- **Privacy & PDPA**: ประมวลผลบนเครื่อง Local ทั้งหมด หมายเลข CID และที่อยู่ละเอียดจะถูกตัดออกก่อนการวิเคราะห์ ไม่มีข้อมูลรั่วไหลออกภายนอก พร้อมปุ่ม **Purge Session** สำหรับล้างข้อมูลทันที
- **ความจุไฟล์**: รองรับไฟล์ DDS Excel ขนาดใหญ่กว่า 10 MB (ตั้งค่าเริ่มต้นไว้สูงสุด 50 MB)

## 📂 โครงสร้างหน้าที่พัฒนาครบถ้วนทั้ง 10 หน้า

1. **Import & Data Quality (นำเข้าและคุณภาพข้อมูล)**: อัปโหลดไฟล์ Excel DDS, ปุ่มโหลดข้อมูลสังเคราะห์ 20,172 รายการ One-Click, ตัวช่วยตรวจสอบคอลัมน์ (Mapping Wizard), และผังการคัดกรองระเบียนอย่างโปร่งใส (Auditable Flow)
2. **Overview (ภาพรวมระบาดวิทยา)**: การคำนวณ 4 ตัวชี้วัดหลัก: ผู้ป่วยเข้าเกณฑ์ $C$, สัดส่วนนอน รพ. $H / (H + O)$ พร้อม 95% Wilson CI, ความสมบูรณ์ประเภทผู้ป่วย $(H + O) / C$, และอัตราป่วยต่อแสนประชากรพร้อม Exact Poisson CI
3. **Time (แนวโน้มตามเวลา)**: Epidemic Curve แบบแท่งซ้อนกัน (OPD, Unknown, IPD) อิงตามระบบสัปดาห์ระบาดวิทยา (Epi Week) และการวิเคราะห์ความล่าช้าในการรายงาน (Reporting Lag)
4. **Districts (การกระจายรายอำเภอ)**: สลับดูที่อยู่ปัจจุบัน (Residence) เทียบกับที่อยู่ขณะป่วย (Illness Location) พร้อมรหัสอำเภอ 4 หลัก (6501–6509), แผนที่ผังอำเภอพิษณุโลก, แผนภูมิแท่งจัดอันดับ และคำชี้แจงสถานะประชากรรายอำเภอ
5. **Person & Rates (บุคคลและอัตราป่วย)**: พีระมิดประชากรผู้ป่วยชาย-หญิงราย 5 ปี, การจำแนกสัญชาติ 3 กลุ่ม (ไทย / ไม่ใช่สัญชาติไทย / ไม่ระบุ), อัตราป่วยต่อแสนประชากร และสัดส่วนนอน รพ. รายกลุ่มอายุ
6. **Summary Tables (ตารางสรุปมาตรฐาน)**: ตารางที่ 0 ถึง 5 ครบถ้วนตามมาตรฐานสำนักระบาดวิทยา พร้อมส่งออกเป็นสมุดงาน Excel (.XLSX) จัดสไตล์สวยงาม และไฟล์ CSV
7. **Associated Factors (ปัจจัยที่มีความสัมพันธ์)**: Multivariable Logistic Regression วิเคราะห์ Adjusted Odds Ratios (aOR) และ Crude OR พร้อมการตรวจจับ Events ไม่เพียงพอ และ Perfect Separation อย่างเข้มงวด
8. **Forecast (การพยากรณ์โรค)**: โมเดลแนวโน้ม OLS ดัชนีเวลาต่อเนื่อง $t$ ข้ามปีระบาด (1–12 สัปดาห์ล่วงหน้า) พร้อมแถบความเชื่อมั่นการทำนาย 80% และ 95% Prediction Intervals และการทดสอบแบบ Rolling-origin
9. **Presentation Studio (ห้องจัดสไลด์ 4K)**: แกลเลอรีสร้างสไลด์ระดับ Ultra HD 3840×2160 พิกเซล (16:9), เวกเตอร์ SVG และ PDF ปรับธีมขาว/ดำได้ และปุ่ม One-Click ดาวน์โหลด **Presentation Pack ZIP**
10. **Methods & Export (ระเบียบวิธีและส่งออก)**: เอกสารทางวิชาการ สูตรทางสถิติ คำชี้แจงข้อจำกัดของข้อมูล DOPA และปุ่มดาวน์โหลดรายงานฉบับเต็ม

## 🚀 คำสั่งเริ่มต้นใช้งาน (Local Setup)

### 1. รัน Backend (FastAPI)
```powershell
cd backend
$env:PYTHONPATH="."
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```
API Documentation: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

### 2. รัน Frontend (React Vite)
```powershell
cd frontend
npm install
npm run dev
```
แอปพลิเคชันจะเปิดที่: [http://127.0.0.1:3000](http://127.0.0.1:3000)

### 3. รันชุดทดสอบความถูกต้องทางสถิติ (Unit Tests)
```powershell
cd backend
$env:PYTHONPATH="."
python -m pytest tests
```
ผ่านการทดสอบ 9 ข้อกำหนดสำคัญ รวมถึงข้อกำหนด:
`10 IPD + 80 OPD + 10 unknown = 100 cases -> Hospitalization % = 11.11%, Completeness = 90%`

## 🔬 หลักการทางระบาดวิทยาที่บังคับใช้อย่างเข้มงวด

- **Hospitalization Proportion (%)**: คำนวณจาก $H / (H + O) \times 100$ และใช้ Wilson Score Interval ไม่นำผู้ป่วยไม่ระบุประเภท (Unknown ~52%) มารวมในตัวหาร และไม่แปลงค่าว่างเป็น OPD โดยเด็ดขาด
- **Population Rates**: ใช้อัตราส่วนกับประชากรที่เข้ากันได้จริง พร้อม Exact Poisson Interval สำหรับอำเภอที่ไม่มีประชากรในเล่ม DOPA จะแสดงสถานะ Unavailable โดยไม่หารเฉลี่ยประชากรจังหวัดเท่ากัน
- **Authoritative Revision Deduplication**: ตรวจสอบลำดับการอัปเดตตาม (CID + กลุ่มโรค + วันเริ่มป่วย) โดยยึดข้อมูลอัปเดตล่าสุดก่อนทำการกรองสถานะ เพื่อป้องกันไม่ให้ข้อมูลเก่าที่เคยอนุมัติฟื้นคืนชีพกลับมาทับข้อมูลที่ถูกยกเลิกในภายหลัง
- **Buddhist Era Date Parsing**: แยกแยะปี พ.ศ. (>= 2400) และปี ค.ศ. อย่างแม่นยำ ไม่ลบ 543 ซ้ำซ้อนกับวันที่ที่เป็น ค.ศ. อยู่แล้ว
